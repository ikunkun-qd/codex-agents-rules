# Codex AGENTS.md 项目协作规则

这是一份可重复使用的 `AGENTS.md` 模板。它的目的很简单：让 Codex 或其他编程 AI 在修改项目之前先了解现状，在长期迭代中记得做到哪里，并在排查 Bug 时少猜、少漏、少乱改。它面向个人 AI 协作场景：`.agent-docs/` 里的文档是给 AI 自己看的备忘、契约和进度记录，不承担团队共享职责。


## 仓库内容

- `AGENTS.md`：给 AI 使用的项目工作规则。
- `README.md`：说明这份规则为什么存在、怎么使用，以及它不能替代什么。

## 它主要解决什么问题

1. **新会话忘记上下文**：先读取 README、`.agent-docs/README.md`（存在时）、项目状态、活动计划、Git 和相关代码。
2. **大型项目找不到相关模块**：可配合 Understand Anything 建立知识图，定位入口、依赖和影响范围。
3. **长期任务不知道做到哪里**：使用 `PROJECT_STATUS.md` 保存当前进度、阻塞项、下一步和最近验证。
4. **前后端或数据库修改不同步**：要求同步检查 API 契约、Schema、Migration、数据字典和测试。
5. **Bug 修复靠猜**：要求先复现、查看请求和日志、确定问题边界，再做最小修改和回归验证。
6. **AI 擅自提交或破坏文件**：没有明确要求时，不执行提交、推送、清理或不可逆操作。
7. **设计和实施脱节**：区分设计文档、实施文档和项目状态，要求它们与 PRD、架构节点和验收记录相互追踪。
8. **对接别人的接口靠猜**：直接读对方源码确认行为，把验证过的请求/响应格式记进个人笔记，不猜不虚构。

## 各工具分别负责什么

- **AGENTS.md**：规定 AI 应该怎么了解、修改和验证项目。
- **Superpowers**：有未完成实施计划时用于按计划续作；未安装时先按规则从 GitHub 安装并配置，安装不成再改用 `PROJECT_STATUS.md` 和 Git 记录续作。
- **Understand Anything**：负责生成项目知识图，帮助查找模块、调用关系和修改影响。
- **PROJECT_STATUS.md**：负责记录项目当前做到哪里，不保存大段历史。
- **代码、日志和测试结果**：始终是判断当前真实情况的最终依据。

## 怎么使用

### 新项目

1. 将 `AGENTS.md` 复制到项目根目录。
   - **前置 Git 检查**：若项目已初始化 Git，首次创建个人文档前将 `.agent-docs/` 写入仓库本地的 `.git/info/exclude`；若尚未初始化 Git（不存在 `.git` 目录），可先在本地直接创建 `.agent-docs/` 记录，待后续执行 `git init` 后第一时间补充写入 `.git/info/exclude`，不阻塞任务。
2. 区分项目规模准备前置文档：对于小型脚本、探索原型（MVP），可仅创建单文件需求与设计说明并初始化 `PROJECT_STATUS.md`；对于正式生产级项目，在首次编写业务代码前创建 `.agent-docs/README.md`、PRD 或经确认的需求记录、功能设计文档、架构总览、首期实施计划和 `PROJECT_STATUS.md`。
3. 按项目实际情况创建 API/数据契约、数据字典、ADR、测试策略、部署/回滚文档、运行手册和可观测性文档；完整目录以 `AGENTS.md` 为准。
4. 项目较小、一次性或纯只读任务可以按规则减少文档；需求不明确时先确认，不由 AI 自行编造业务规则。

### 已有项目或公司项目

1. 先检查项目中是否已经存在 `AGENTS.md` 或同类规则。
2. 已有规则和文档只读参考；个人维护内容复制到当前项目的个人 `.agent-docs/` 目录，不修改原有文件；任何项目都不改其 `.gitignore` 和已有目录，用仓库本地的 `.git/info/exclude` 忽略个人目录。
3. 先查找已有 PRD、设计文档、实施计划、架构文档、契约、数据字典、测试和运行资料；需要个人记录时复制到 `.agent-docs/` 对应位置。
4. 项目预计跨多个会话、计划或模块且没有个人状态文件时，在首次实施前创建 `PROJECT_STATUS.md`，一次性小改动和纯只读任务可以不创建。

## 重要说明

- 这份文件是“工作规则”，不是项目说明书，也不会自动保存所有项目知识。
- 个人文档目录固定为 `.agent-docs/`，所有项目通用：不改任何项目的 `.gitignore` 和已有目录，首次创建前把 `.agent-docs/` 加入仓库本地的 `.git/info/exclude`（只在本机生效，不影响他人）。若项目尚未初始化 Git（无 `.git/` 目录），可在 `git init` 完成后第一时间补充写入，未初始化前不阻塞个人文档创建。该目录不进 Git、没有版本备份，重要内容需定期自行备份。
- 知识图只能帮助导航，不能代替真实代码、运行日志和测试结果。
- `PROJECT_STATUS.md` 记录当前进度、文档指针以及关联 commit/PR 或未提交变更状态；设计文档回答目标、边界和原因，数据字典记录数据模型和业务语义，实施文档回答落地步骤；Superpowers计划只说明准备怎么做，不单独证明任务已经完成。
- Understand Anything、Superpowers没有安装时，AI先按规则帮助用户从 GitHub 安装并配置好环境；安装失败或环境不允许时，再退回用代码搜索、Git、调用链和测试完成任务。规则里的工具命令名以实际安装版本为准，不一致时按工具帮助确认。
- 工具命令或团队规范变化后，应重新检查并更新这份模板。
